Pipeline не запускается сам по себе — ему нужен сигнал. Этот сигнал называется триггером (trigger). Триггер определяет, при каком событии система CI/CD должна начать выполнение цепочки этапов.

**Push**
Pipeline запускается каждый раз, когда разработчик отправляет коммит в репозиторий. Это основа непрерывной интеграции: код попал в ветку — немедленно запустилась проверка. Пример конфигурации в GitLab CI:

```
stages:
  - build
  - test

build-job:
  stage: build
  script:
    - echo "Building..."
  rules:
    - if: '$CI_PIPELINE_SOURCE == "push"'
```

На практике push-триггер ограничивают: например, только для веток `main`, `develop` или по маске `feature/*`.

**Merge Request**
Триггер по merge request (merge request trigger, в GitHub — pull request trigger) срабатывает, когда разработчик создаёт или обновляет запрос на слияние веток. Это ключевой момент code review: pipeline проверяет код до того, как он попадёт в основную ветку. Такой pipeline часто называют проверочным (validation pipeline) — он может включать линтеры, юнит-тесты и статический анализ, но не деплой в продакшен. Это защищает главную ветку от сломанного кода.

**Schedule**
Расписание (scheduled trigger, cron trigger) запускает pipeline по времени, независимо от активности разработчиков. Расписание задаётся в формате cron.

**Manual**
Ручной триггер (manual trigger) требует явного действия человека — нажатия кнопки в интерфейсе или вызова через API. Pipeline не запустится автоматически, пока кто-то не даст разрешение.

Это незаменимо для деплоя в продакшен: автоматическая сборка и тесты проходят без участия человека, но финальный шаг развёртывания ждёт подтверждения ответственного инженера или тимлида.

```
deploy-production:
  stage: deploy
  script:
    - ./deploy.sh production
  when: manual
  only:
    - main
```

Ключевое слово `when: manual` говорит системе: не запускать этот шаг автоматически. В интерфейсе GitLab рядом с таким шагом появится кнопка «Play», которую нужно нажать вручную.

На практике триггеры комбинируют (на каждый триггер своя задача).
