Когда вы запускаете контейнер, Docker берёт все слои образа (они остаются read-only) и добавляет поверх них тонкий записываемый слой (writable layer), который принадлежит только этому контейнеру.

Схема выглядит так:
![20261020125840](../resources/20261020125840.png)

Любые изменения внутри работающего контейнера — созданные файлы, логи, изменённые конфиги — попадают только в writable layer. Слои образа при этом не затрагиваются.

Запустить 10 контейнеров из одного образа дёшево — каждый добавляет лишь небольшой writable layer, а сам образ не копируется.

Когда контейнер удаляется, его writable layer уничтожается вместе с ним. Всё, что туда записалось, теряется.

Когда процесс внутри контейнера пытается изменить файл из read-only слоя, Docker не трогает оригинал. Вместо этого он копирует файл в writable layer и уже там применяет изменения. Этот механизм называется Copy-on-Write (CoW).

# Жизненный цикл контейнера
С момента создания до удаления контейнер проходит через несколько чётко определённых состояний (states), и каждое состояние соответствует конкретной команде Docker CLI.

![20261020130505](../resources/20261020130505.png)

Переходы не обязательно линейны.

Created. Команда `docker create` резервирует файловую систему и конфигурацию, но не запускает процесс. Это удобно, когда нужно подготовить контейнер заранее и запустить его позже.

Running. Основной процесс (указанный в `CMD` или `ENTRYPOINT` образа) активен. Именно в этом состоянии контейнер потребляет CPU и память.

Paused. Команда `docker pause` отправляет сигнал `SIGSTOP` всем процессам контейнера. Они замирают — не потребляют CPU, но остаются в памяти. `docker unpause` возобновляет работу с той же точки. Это полезно при отладке: можно «заморозить» контейнер и изучить его состояние.

Stopped (exited). Команда `docker stop` сначала отправляет `SIGTERM`, даёт процессу 10 секунд на корректное завершение, затем — `SIGKILL`. `docker kill` отправляет `SIGKILL` немедленно. Файловая система контейнера при этом сохраняется — данные не теряются до удаления.

Removed. `docker rm` удаляет контейнер и его writable layer. Образ остаётся нетронутым. Удалить работающий контейнер без остановки можно принудительно: `docker rm -f`.

Проверить текущее состояние контейнера в любой момент позволяет команда: `docker inspect --format '{{.State.Status}}' lifecycle-demo`.

Попытка удалить работающий контейнер без флага `-f` завершится ошибкой. Нужно сначала остановить контейнер.

# docker run
Команда `docker run` запускает контейнер из образа. Без флагов она работает, но в реальных задачах почти всегда нужна точная настройка.

Флаг `-d` (detached) запускает контейнер в фоне. Терминал сразу возвращает управление, а контейнер продолжает работать: `docker run -d nginx`.

Флаг `-it` — сочетание двух флагов: `-i` (interactive, держать stdin открытым) и `-t` (tty, подключить псевдотерминал). Вместе они дают интерактивную сессию внутри контейнера. Используется, когда нужно «зайти» в контейнер и работать в командной строке: `docker run -it ubuntu bash`. Если не указать команду может возникнуть ошибка, так как некоторые образы не имеют shell по умолчанию и нужно указывать `bash` или `sh` явно

По умолчанию Docker присваивает контейнеру случайное имя. Флаг `--name` задаёт понятное имя, по которому удобно обращаться к контейнеру в других командах.

Флаг `--rm` удаляет контейнер сразу после его остановки. Полезен для разовых задач, чтобы не засорять список остановленных контейнеров: `docker run --rm --name test-nginx -d nginx`.

Контейнер изолирован от хостовой сети. Чтобы сервис внутри контейнера был доступен снаружи, нужно пробросить порт (port binding). Синтаксис: `-p <порт_хоста>:<порт_контейнера>`: `docker run -d --name web -p 8080:80 nginx`. После этого запроса `http://localhost:8080` на хосте будет отвечать Nginx, слушающий порт 80 внутри контейнера.

Флаг `-e` (environment) передаёт переменную окружения (environment variable) внутрь контейнера. Флаг `-e` можно указывать несколько раз — каждый раз для одной переменной.

```
docker run -d \
  --name db \
  -e POSTGRES_USER=admin \
  -e POSTGRES_PASSWORD=secret \
  -e POSTGRES_DB=myapp \
  -p 5432:5432 \
  postgres
```
