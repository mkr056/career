Docker при запуске контейнера автоматически создаёт отдельную cgroup для каждого контейнера и прописывает туда все его процессы. 

Когда вы запускаете контейнер с флагами ресурсов, Docker транслирует их в настройки cgroup. Например: `docker run --memory="256m" --cpus="0.5" nginx`.  Эта команда создаёт контейнер, которому доступно не более 256 МБ оперативной памяти и половина одного ядра CPU. Если контейнер приближается к лимиту памяти, ядро может пытаться освободить память, в том числе используя swap, если он доступен и разрешён настройками. Если освободить достаточно памяти не удаётся, может сработать OOM-killer, который завершит один или несколько процессов. Конкретное поведение зависит от конфигурации cgroup, доступности swap и состояния памяти на хосте.

Флаг --memory-swap позволяет отдельно ограничить суммарный объём RAM + swap. Если установить его равным значению --memory, swap для контейнера будет полностью отключён: `docker run --memory="256m" --memory-swap="256m" nginx`.

Ограничение I/O задаётся через --device-read-bps и --device-write-bps — они ограничивают скорость чтения и записи на конкретное блочное устройство: `docker run --device-write-bps /dev/sda:10mb nginx`.

Посмотреть реальные лимиты работающего контейнера можно напрямую в файловой системе `/sys/fs/cgroup`:  `cat /sys/fs/cgroup/memory/docker/<container_id>/memory.limit_in_bytes` либо через `docker inspect`.

Типичная ошибка: контейнер без лимитов.
