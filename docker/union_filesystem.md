Когда Docker запускает контейнер из образа, он не копирует весь образ на диск заново. Вместо этого используется объединяющая файловая система (union filesystem) — механизм, позволяющий накладывать несколько директорий друг на друга так, что снаружи они выглядят как одна.

Каждый образ Docker состоит из слоёв (layers). Каждый слой — это набор изменений файловой системы: добавленные файлы, удалённые файлы, изменённые права доступа. Слои неизменяемы (read-only) и хранятся на диске один раз, независимо от того, сколько контейнеров их используют.

Когда десять контейнеров запущены на одном образе, они все читают одни и те же слои на диске. Это экономит гигабайты пространства.

Контейнер не может изменить read-only слои образа. Поэтому поверх них добавляется тонкий слой записи (writable layer, или container layer). Он принадлежит конкретному контейнеру и исчезает вместе с ним при удалении.

Механизм copy-on-write (CoW) работает так: пока контейнер только читает файл из нижних слоёв — копирования не происходит. Как только контейнер пытается изменить файл, система копирует его в верхний слой записи, и все дальнейшие операции идут с копией. Исходный файл в нижних слоях остаётся нетронутым.

Это объясняет, почему запуск контейнера занимает миллисекунды: не нужно копировать гигабайты данных — достаточно создать пустой слой записи.

Современный Docker по умолчанию использует драйвер overlay2 — реализацию union filesystem, встроенную в ядро Linux. Он работает с двумя директориями:
- `lowerdir` — один или несколько read-only слоёв образа;
- `upperdir` — слой записи контейнера;
- `merged` — объединённое представление, которое видит процесс внутри контейнера.

Посмотреть, какой драйвер использует ваш Docker, можно командой: `docker info | grep "Storage Driver"`.

Детали слоёв конкретного образа показывает команда: `docker image inspect nginx --format '{{json .RootFS.Layers}}'`. Вы увидите список SHA256-хешей — каждый хеш соответствует одному слою на диске.


Разработчики иногда думают, что данные, записанные в контейнер, сохранятся после его удаления. Это не так — слой записи уничтожается вместе с контейнером. Для постоянного хранения используют тома (volumes).
