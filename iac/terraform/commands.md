Работа с Terraform строится вокруг четырёх команд, которые выполняются в строгом порядке. Пропустить шаг нельзя — каждая команда готовит почву для следующей. Этот порядок называют жизненным циклом Terraform.

**terraform init**
Первая команда, которую запускают в любом новом проекте или после изменения конфигурации провайдеров. `terraform init` выполняет три вещи: скачивает провайдеры (plugins) в папку `.terraform/providers/` и фиксирует их хеши в файле `.terraform.lock.hcl`, инициализирует backend — место хранения state-файла, и создаёт служебную директорию `.terraform/`. После успешного выполнения в директории появится `.terraform/` и файл `.terraform.lock.hcl`. Без `init` не заработают команды, которым нужны провайдеры и backend: `plan`, `apply`, `destroy`, `validate`.

**terraform plan**
Команда строит план изменений (execution plan): Terraform читает конфигурацию, сравнивает её с текущим состоянием инфраструктуры и показывает, что будет создано, изменено или удалено. Реальных изменений не происходит. В выводе каждый ресурс помечается символом: `+` — создать, `~` — изменить, `-` — удалить, `-/+` — пересоздать,. Это ревью перед тем, как что-то применять. Опытные инженеры сохраняют план в файл, чтобы `apply` применил именно его:

```
terraform plan -out=tfplan
terraform apply tfplan
```

**terraform apply**
Применяет изменения к реальной инфраструктуре. Если запустить без сохранённого плана, Terraform сначала построит новый план и попросит подтверждение (`yes`).

После успешного выполнения Terraform обновляет файл состояния — `terraform.tfstate`. Этот файл — источник правды о том, какие ресурсы Terraform считает существующими. Удалять его вручную нельзя.

Флаг `-auto-approve` пропускает интерактивное подтверждение — используется в CI/CD пайплайнах: `terraform apply -auto-approve`

**terraform destroy**
Удаляет все ресурсы, описанные в конфигурации. Порядок удаления Terraform определяет сам, учитывая зависимости между ресурсами. Команда тоже показывает план перед удалением и запрашивает подтверждение. В продакшене её используют осторожно — восстановить удалённые облачные ресурсы обычно невозможно.

Чаще всего ошибаются так: запустить `apply` после изменения версии провайдера без повторного `init`. Terraform выдаст ошибку о несоответствии плагинов. Правило простое: изменил блок `required_providers` — запустите `init` заново.

**terraform show**
Команда `terraform show` выводит содержимое файла состояния (state) или сохраненного файла плана (plan) в удобном для чтения человеком виде или в формате JSON.

**terraform output**
Команда `terraform output` извлекает и отображает значения выходных переменных (outputs) из текущего файла состояния (state).

**terraform validate**
Команда `terraform validate` проверяет конфигурационные файлы Terraform на синтаксическую корректность и внутреннюю согласованность без обращения к реальной инфраструктуре, облачным провайдерам или файлу состояния (state).
