Когда инфраструктура разрастается, держать всё в одном `main.tf` становится неудобно: файл превращается в сотни строк, повторяющиеся блоки копируются вручную, а изменение одного ресурса требует правок в десятках мест. Модуль в Terraform — это способ упаковать набор ресурсов в переиспользуемую единицу, похожую на функцию в программировании.

Любая директория с `.tf`-файлами уже является модулем. Когда вы запускаете `terraform apply` в рабочей директории, вы работаете с **корневым модулем (root module)**. Дочерние модули — это отдельные директории, которые корневой модуль вызывает через блок `module {}`.

Типичная структура проекта с модулем выглядит так:

```
project/
  main.tf          # корневой модуль
  modules/
    vpc/
      main.tf      # ресурсы VPC
      variables.tf # входные переменные модуля
      outputs.tf   # выходные значения модуля
```

**Параметр source**
Блок `module {}` обязательно содержит аргумент `source` — путь к директории с модулем или ссылку на реестр. Terraform поддерживает несколько форматов:

```
# Локальный путь
module "vpc" {
  source = "./modules/vpc"
}

# Публичный реестр Terraform Registry
module "vpc" {
  source  = "terraform-aws-modules/vpc/aws"
  version = "5.1.0"
}

# Git-репозиторий
module "vpc" {
  source = "git::https://github.com/org/repo.git//modules/vpc?ref=v1.0"
}
```

После добавления нового `source` необходимо выполнить `terraform init`, чтобы Terraform скачал модуль.

**Входные переменные модуля**
Модуль принимает данные через входные переменные, объявленные в `variables.tf` модуля:

```
# modules/vpc/variables.tf
variable "cidr_block" {
  type        = string
  description = "CIDR для VPC"
}

variable "environment" {
  type    = string
  default = "dev"
}
```

При вызове модуля значения передаются как аргументы блока:

```
# main.tf (корневой модуль)
module "vpc" {
  source     = "./modules/vpc"
  cidr_block = "10.0.0.0/16"
  environment = "production"
}
```

Переменные без `default` обязательны — Terraform выдаст ошибку, если их не передать.

**Выходные значения модуля**
Чтобы корневой модуль мог использовать данные, созданные внутри дочернего, модуль публикует выходные значения:

```
# modules/vpc/outputs.tf
output "vpc_id" {
  value       = aws_vpc.main.id
  description = "ID созданного VPC"
}
```

В корневом модуле к этому значению обращаются через синтаксис `module.<имя_модуля>.<имя_output>`:

```
# main.tf
resource "aws_subnet" "public" {
  vpc_id     = module.vpc.vpc_id
  cidr_block = "10.0.1.0/24"
}
```

Распространённый промах — обращаться к внутренним ресурсам модуля напрямую, например `module.vpc.aws_vpc.main.id`. Это не работает: снаружи видны только явно объявленные `output`-блоки.

Такой подход позволяет создать, например, один модуль `vpc` и вызывать его несколько раз с разными параметрами — для `staging` и `production` — без дублирования кода ресурсов.
