Провайдер в Terraform — это плагин, который умеет общаться с конкретным API: облачным, SaaS-сервисом или локальной системой. Без провайдера Terraform не знает, что такое `aws_instance` или `yandex_compute_instance` — это просто незнакомые слова. Провайдер переводит HCL-описание ресурса в реальные API-вызовы.

Официальные провайдеры публикуются в реестре Terraform по адресу `registry.terraform.io`. Каждый провайдер идентифицируется по схеме `<namespace>/<name>`: `hashicorp/aws`, `hashicorp/azurerm`, `hashicorp/google`, `yandex-cloud/yandex`. Yandex Cloud — пример провайдера от стороннего вендора, не HashiCorp. Именно поэтому его namespace отличается.

**Блок required_providers**
Провайдеры объявляются в блоке `terraform` внутри `required_providers`. Это обязательная декларация: она говорит Terraform, откуда скачать плагин и какую версию считать допустимой.

```
terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
    yandex = {
      source  = "yandex-cloud/yandex"
      version = ">= 0.90.0"
    }
  }
}
```

Ограничение версии задаётся строкой с оператором:

- `"~> 5.0"` — разрешает любой патч и минор в пределах `5.x`, но не `6.0`.
- `">= 0.90.0"` — разрешает эту версию и выше.
- `"= 5.31.0"` — строго одна версия, без обновлений.

Для продакшена рекомендуется `~>`: вы получаете патчи безопасности, но защищены от ломающих изменений при переходе на следующий мажор.

# Файл .terraform.lock.hcl
Lock-файл фиксирует точную версию каждого провайдера и криптографические хэши его бинарников.

Три ключевых поля:
- `version`: Точная версия, которую скачал Terraform
- `constraints`: Ограничение из блока `required_providers`
- `hashes`: SHA-256 хэши бинарников для разных платформ

Когда вы сознательно хотите перейти на новую версию провайдера, используйте флаг `-upgrade`: `terraform init -upgrade`

Terraform скачает последнюю версию в рамках ваших ограничений и обновит `.terraform.lock.hcl`. После этого нужно проверить изменения в файле через `git diff` и закоммитить обновлённый lock-файл.

`.terraform.lock.hcl` всегда коммитится в репозиторий. Это не артефакт сборки — это часть исходного кода инфраструктуры. Папку `.terraform/` при этом добавляют в `.gitignore`, потому что она содержит скачанные бинарники провайдеров, которые весят десятки мегабайт и не должны храниться в Git.

Типовой `.gitignore` для Terraform-проекта:

```
.terraform/
*.tfstate
*.tfstate.backup
```
