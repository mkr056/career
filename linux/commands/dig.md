`dig ИМЯ ТИП` — стандартный инструмент, чтобы спросить у DNS конкретную запись. Его вывод разбит на секции:

```
; <<>> DiG 9.18 <<>> example.com A
;; status: NOERROR, id: 42

;; QUESTION SECTION:
;example.com.            IN   A

;; ANSWER SECTION:
example.com.      300   IN   A     93.184.216.34
example.com.      300   IN   A     93.184.216.35
```

Что здесь важно:
- Строки, начинающиеся с `;` — это комментарии и заголовки секций (`;; QUESTION SECTION`, сама строка вопроса `;example.com.`). Их при разборе пропускают.
- `status:` — итог запроса. NOERROR — сервер ответил штатно. NXDOMAIN — такого имени нет вообще. Это разные вещи: NXDOMAIN значит «записи нет», а вот если сервер вовсе не ответил (таймаут, SERVFAIL) — проблема не в имени, а в самом DNS-сервере.
- ANSWER SECTION — здесь лежит результат. Каждая строка ответа идёт по колонкам: `имя TTL класс(IN) тип значение`. Для строки `example.com. 300 IN A 93.184.216.34` это: имя `example.com.`, TTL `300`, класс `IN`, тип `A`, значение `93.184.216.34`.
- Тип записи — это 4-я колонка, значение — 5-я (последняя).

Есть краткий режим `dig +short ИМЯ ТИП` — он печатает только значения, без секций, по одному на строку.
