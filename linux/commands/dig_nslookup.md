`dig ИМЯ ТИП` — стандартный инструмент, чтобы спросить у DNS конкретную запись. Его вывод разбит на секции:

```
; <<>> DiG 9.18 <<>> example.com A
;; status: NOERROR, id: 42

;; QUESTION SECTION:
;example.com.            IN   A

;; ANSWER SECTION:
example.com.      300   IN   A     93.184.216.34
example.com.      300   IN   A     93.184.216.35
```

Что здесь важно:
- Строки, начинающиеся с `;` — это комментарии.
- `status:` — итог запроса. NOERROR — сервер ответил штатно. NOERROR, но `ANSWER: 0` — имя есть, но записи нужного типа нет. NXDOMAIN — такого имени нет вообще. Это разные вещи: NXDOMAIN значит «записи нет», а вот если сервер вовсе не ответил (таймаут, SERVFAIL) — проблема не в имени, а в самом DNS-сервере.
- ANSWER SECTION — здесь лежит результат. Каждая строка ответа идёт по колонкам: `имя TTL класс(IN) тип значение`. Для строки `example.com. 300 IN A 93.184.216.34` это: имя `example.com.`, TTL `300`, класс `IN`, тип `A`, значение `93.184.216.34`.
- Тип записи — это 4-я колонка, значение — 5-я (последняя).

Важный нюанс для парсинга: у `A`, `AAAA`, `CNAME`, `NS` значение — это 5-е поле. А у `MX` между типом и именем сервера вклинивается приоритет (`example.com. 3600 IN MX 10 mail.example.com.`), поэтому число полей у разных типов различается.

Есть краткий режим `dig +short ИМЯ ТИП` — он печатает только значения, без секций, по одному на строку.

`nslookup` решает ту же задачу проще, но грубее: печатает `Name:` и `Address:` без TTL и типов. Блок `Server` и `Address`. Показывает имя и IP-адрес того DNS-сервера, который обработал ваш запрос. Блок `Name` и `Addresses`. Содержит искомый домен и найденные для него записи. Пометка `Non-authoritative answer` означает, что ответ получен из кэша промежуточного (рекурсивного) DNS-сервера, а не напрямую с сервера, хранящего оригинальные файлы зоны домена. Это нормальное поведение при обычных проверках.
