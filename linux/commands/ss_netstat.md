Две команды показывают все сокеты хоста прямо сейчас:
- `ss` — современная утилита (socket statistics), быстрая, из пакета iproute2;
- `netstat` — классика, тот же смысл, чуть другой синтаксис, местами медленнее.

Они отвечают на два ежедневных вопроса: «какие порты сейчас открыты на сервере (и кто их слушает)?» и «какие сетевые соединения активны в данный момент?».

Ключи `ss` собираются из букв-флагов:
`-t`: TCP-сокеты
`-u`: UDP-сокеты
`-l`: только listening (слушающие)
`-n`: numeric — не резолвить имена, показывать номера портов и IP как есть
`-a`: all — и слушающие, и установленные

Флаг `-n` важен: без него `ss` попытается превратить `:443` в `:https`, а `:80` в `:http` — и в скриптах это только мешает. Числовой вывод детерминирован и легко парсится `awk`. У `netstat` те же идеи: `netstat -tlnp` — слушающие TCP с номером порта и (при правах) процессом, который их держит.

Вывод:
```
State   Recv-Q Send-Q Local Address:Port  Peer Address:Port
LISTEN  0      128    0.0.0.0:22          0.0.0.0:*
LISTEN  0      128    127.0.0.1:5432      0.0.0.0:*
ESTAB   0      0      10.0.0.5:443        10.0.0.9:51512
```

- State — состояние сокета
- Recv-Q / Send-Q — сколько байт застряло в очереди приёма/отправки (для слушающих `Send-Q` — это backlog, длина очереди ожидающих коннектов)
- Local Address:Port — своя сторона: на каком адресе и порту сидит этот сокет у нас
- Peer Address:Port — собеседник: удалённый адрес и порт (у слушающих там заглушка `0.0.0.0:*` или `*:*` — собеседника ещё нет)

Важнейшие состояния, которые встречаются в выводе:
- LISTEN — серверный сокет ждёт входящих. Это ответ на «кто слушает порт»
- ESTAB (полное имя `ESTABLISHED`) — соединение установлено, идёт обмен. Это и есть материализованная четвёрка: локальный IP:порт + удалённый IP:порт
- TIME-WAIT — соединение недавно штатно закрыто, ОС ещё придерживает порт (защита от «заблудившихся» пакетов)
- SYN-SENT / SYN-RECV — рукопожатие в процессе, коннект ещё не достроен

Запомните пару: `ss` пишет активные коннекты как `ESTAB`, а `netstat` — как `ESTABLISHED`. Это одно и то же состояние; в скриптах учитывайте оба написания.

Самая частая загадка — «локально работает, а снаружи не достучаться». Ответ прячется в Local Address слушающего сокета. Адрес привязки говорит, с каких интерфейсов примут коннект:

- `0.0.0.0:80` — слушаю на всех IPv4-интерфейсах, доступно снаружи
- `*:80` — то же самое «на всех» (так пишут некоторые версии `ss`/`netstat`)
- `[::]:80` — «на всех» для IPv6
- `127.0.0.1:5432` — только loopback, доступно лишь с самой машины; снаружи будет `Connection refused`/timeout
- `[::1]:3000` — IPv6-loopback, тоже только локально
- `192.168.1.10:8080` — привязка к одному конкретному интерфейсу

Типичный баг: Postgres или дев-сервер поднят на `127.0.0.1`, а вы ломитесь по внешнему IP. `ss` честно показывает `LISTEN 127.0.0.1:5432` — сервис жив, но заперт внутри.
