cron — системная служба, которая запускает команды автоматически по заданному расписанию.

Демон (daemon) — это программа, которая работает в фоне постоянно, без участия пользователя. Демон cron запускается при старте системы и продолжает работать всё время, пока система включена. Каждую минуту он проверяет: есть ли задачи, которые нужно выполнить прямо сейчас? Если есть — запускает их.

Убедиться, что cron работает, можно командой: `systemctl status cron`.

На большинстве систем Debian/Ubuntu служба называется cron, на системах на базе Red Hat — crond. Вывод покажет строку Active: active (running), если демон запущен.

Каждый пользователь системы имеет собственный crontab (cron table) — текстовый файл с расписанием его задач. Система хранит эти файлы в /var/spool/cron/crontabs/. Напрямую редактировать файлы в этой директории не нужно: для этого есть специальная команда. Помимо пользовательских crontab, в системе есть общесистемные файлы расписаний:
- /etc/crontab: Системный crontab (редактируется вручную root-ом)
- /etc/cron.d/: Директория с дополнительными расписаниями от пакетов
- /etc/cron.daily/: Скрипты, запускаемые раз в сутки
- /etc/cron.hourly/: Скрипты, запускаемые раз в час

Важная особенность: cron запускает задачи в минимальном окружении (environment). Это означает, что переменная PATH внутри cron содержит только базовые пути вроде /usr/bin и /bin. Если ваш скрипт использует команду, которая находится в другом месте, cron её не найдёт. Поэтому в задачах cron принято указывать полные пути к командам и файлам.

Вывод команд, которые запускает cron, по умолчанию отправляется на почту пользователя внутри системы. Чтобы этого избежать и сохранить вывод в файл, используют перенаправление — например, дописывают >> /tmp/task.log 2>&1 в конец строки расписания.

Каждая задача в crontab — это одна строка с жёстко заданной структурой.

Строка состоит из шести частей, разделённых пробелами: `минута   час   день_месяца   месяц   день_недели   команда`.

Первые пять частей описывают когда запускать задачу, шестая — что запускать. Порядок полей фиксирован и не меняется.

Звёздочка * в любом поле означает «каждое возможное значение». Именно поэтому * * * * * команда запускает задачу каждую минуту — все пять полей разрешают любое значение.

Crontab (crontab file) — персональный файл расписания каждого пользователя. Напрямую редактировать его не рекомендуется: cron может не заметить изменения или файл окажется повреждён. Вместо этого используют две команды.

crontab -e открывает файл расписания в текстовом редакторе (обычно nano или vi). После сохранения и выхода cron автоматически применяет изменения.

crontab -l выводит текущее содержимое файла расписания прямо в терминал, не открывая редактор. Удобно, чтобы быстро проверить, какие задачи уже настроены.

Если расписание пустое, команда либо ничего не выведет, либо сообщит no crontab for user.

Конструкция /N задаёт шаг. \*/N читается как «каждые N единиц, начиная с минимального значения поля».
