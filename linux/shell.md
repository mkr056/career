Shell (оболочка) — это программа, которая принимает команды пользователя, интерпретирует их и выполняет встроенные команды или запускает другие программы.

Bash (Bourne Again SHell) — одна из наиболее распространённых командных оболочек, особенно в Linux. Zsh, Fish и Dash — другие командные оболочки. Терминал обычно запускает оболочку по умолчанию, настроенную для пользователя, но может быть настроен на запуск другой оболочки или вообще другой программы.

Когда вы нажимаете Enter, оболочка выполняет несколько шагов:
1. Читает введённую команду.
2. Разбирает её: команды, аргументы, операторы, переменные, перенаправления и т. д.
3. Определяет, что нужно выполнить: alias, функцию, встроенную команду оболочки или внешнюю программу.
4. Если это внешняя программа, оболочка ищет её в каталогах из PATH.
5. Запускает программу и передаёт ей аргументы.
6. Если команда запущена в обычном режиме, оболочка ждёт её завершения и получает код завершения. Если команда запущена в фоне, оболочка продолжает работу, не дожидаясь её завершения.
7. Показывает prompt и ждёт следующую команду.

Приглашение ввода (prompt) — строка, которую оболочка показывает, когда готова принять следующую команду. В стандартной конфигурации знак $ обычно используется для обычного пользователя, а # — для пользователя root (суперпользователь). Конкретный вид prompt зависит от используемой оболочки и её настроек.

Оболочка не знает о каждой программе в системе заранее. Если команда не является alias, функцией или встроенной командой, оболочка ищет соответствующий исполняемый файл в каталогах, перечисленных в переменной PATH. Если исполняемый файл найден — оболочка запускает его. Если нет — вы увидите сообщение об ошибке.

Оболочка умеет работать в двух режимах. Интерактивный режим — это то, с чем вы работаете в терминале: вводите команды вручную, получаете ответ. Неинтерактивный режим используется, когда оболочка выполняет команды без непосредственного взаимодействия с пользователем, например при запуске скрипта. Оба режима используют один и тот же синтаксис.

Когда вы открываете терминал или подключаетесь к серверу по SSH, оболочка не просто запускается — он читает определённые файлы конфигурации и выполняет команды из них. Именно там хранятся переменные окружения, псевдонимы и настройки, которые вы хотите иметь в каждой сессии.

Два типа запуска оболочки:
- Оболочка входа (login shell) — запускается при входе в систему: через SSH, через виртуальную консоль (tty), или явно командой bash --login. В этом режиме bash читает файлы аутентификации и инициализации сессии.
- Интерактивная оболочка без входа (interactive non-login shell) — запускается при открытии нового окна терминала в графической среде (GNOME Terminal, iTerm2) или при вызове bash без флагов внутри уже открытой сессии.

Представьте: вы добавили alias в `~/.bashrc`, но при входе по SSH он не работает. Причина — SSH создаёт login shell, а login shell читает `~/.bash_profile`, но не `~/.bashrc`.

Стандартное решение — явно вызвать `.bashrc` из `.bash_profile`:
```
# ~/.bash_profile
if [ -f ~/.bashrc ]; then
    . ~/.bashrc
fi
```

Точка перед `~/.bashrc` — это команда `source`, которая выполняет файл в текущей оболочке, а не в дочернем процессе. После такой настройки и SSH-сессии, и терминальные окна будут использовать одни и те же настройки из `~/.bashrc`.

Файл `~/.profile` — наследие POSIX-совместимых оболочек (sh, dash). Он не содержит bash-специфичного синтаксиса и читается bash только как запасной вариант при отсутствии `~/.bash_profile`. В Ubuntu по умолчанию `~/.bash_profile` не создаётся, поэтому там активен `~/.profile` — и он уже содержит строку, которая подключает `~/.bashrc`:

```
# Фрагмент из ~/.profile в Ubuntu
if [ "$BASH" ]; then
    if [ -f ~/.bashrc ]; then
        . ~/.bashrc
    fi
fi
```

Именно поэтому на Ubuntu настройки в `~/.bashrc` работают и в SSH-сессиях — не магия, а явный вызов внутри `~/.profile`.
