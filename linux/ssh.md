Когда нужно управлять удалённым сервером — будь то облачный VPS, рабочий сервер компании или Raspberry Pi в соседней комнате — физически сидеть рядом с ним необязательно. Для этого существует протокол SSH (Secure Shell): он позволяет открыть терминальный сеанс на удалённой машине через сеть, передавая все данные в зашифрованном виде.

До SSH системные администраторы использовали Telnet — протокол, который передаёт данные открытым текстом. Перехватить пароль в такой сети мог любой, кто слушал трафик. SSH решил эту проблему: соединение шифруется с первого байта, включая аутентификацию.

Базовый синтаксис команды ssh такой: `ssh user@host`.
- user — имя учётной записи на удалённой машине (не на вашей локальной);
- host — IP-адрес или доменное имя сервера.


После выполнения команды сервер попросит ввести пароль (если не настроена аутентификация по ключу). Когда пароль принят, вы окажетесь внутри терминала удалённой машины — точно так же, как если бы сидели за ней физически.

При первом соединении с новым сервером SSH выводит предупреждение:
```
The authenticity of host '192.168.1.10 (192.168.1.10)' can't be established.
ECDSA key fingerprint is SHA256:...
Are you sure you want to continue connecting (yes/no/[fingerprint])?
```

Это проверка отпечатка (fingerprint) — уникального идентификатора сервера. Введите yes, и SSH запомнит этот сервер в файле ~/.ssh/known_hosts. При следующих подключениях предупреждение не появится. Если же отпечаток изменился (например, сервер переустановили), SSH предупредит об этом — это защита от подмены сервера.

Чтобы выйти из удалённого сеанса, достаточно ввести: `exit`.

Соединение закроется, и вы вернётесь в локальный терминал. Альтернативно работает сочетание клавиш Ctrl+D.

Если написать просто ssh 192.168.1.10 без указания user@, SSH использует имя вашего текущего локального пользователя. На сервере такой учётной записи может не быть, и подключение завершится ошибкой Permission denied.

На практике серверы часто слушают нестандартный порт, а пароли как метод аутентификации во многих организациях запрещены. Для этих случаев у ssh есть два ключевых флага.

По умолчанию SSH работает на порту 22. Системные администраторы нередко меняют его на другой — например, 2222 или 8022 — чтобы снизить количество автоматических атак на сервер.

Флаг -p (port) задаёт номер порта явно. Если порт не указан, ssh всегда пробует 22. Попытка подключиться без флага к серверу на нестандартном порту завершится ошибкой Connection refused.

Аутентификация по ключу (key-based authentication) — основной способ входа на серверы в профессиональной среде. Вместо пароля используется криптографическая пара: закрытый ключ (private key) хранится у вас на машине, открытый ключ (public key) — на сервере.

Флаг -i (identity file) указывает путь к файлу закрытого ключа: `ssh -i ~/.ssh/id_rsa alice@192.168.1.10`. Если ключ лежит в стандартном месте (~/.ssh/id_rsa), ssh найдёт его сам и флаг -i можно опустить. Но когда у вас несколько ключей для разных серверов, явное указание обязательно.

При аутентификации по ключу закрытый ключ никогда не покидает вашу машину — сервер лишь проверяет математическое соответствие. Именно поэтому ключи считаются надёжнее паролей: даже если трафик перехватят, получить из него ключ невозможно.

Типовая ошибка при работе с ключами — неправильные права доступа на файл. Если права слишком открытые, ssh откажется использовать ключ и выдаст предупреждение.

Чтобы воспользоваться аутентификацией по ключу, нужно сначала создать саму пару ключей. Для этого служит команда ssh-keygen.

Пара ключей (key pair) состоит из двух файлов:
- Закрытый ключ (private key) — хранится только у вас на машине, никому не передаётся.
- Открытый ключ (public key) — копируется на сервер, к которому вы хотите подключаться.

Аналогия: открытый ключ — это замок, который вы вешаете на чужую дверь. Закрытый ключ — единственный ключ, который этот замок открывает. Даже если кто-то скопирует замок, без вашего ключа он бесполезен.

Базовая команда без аргументов: `ssh-keygen`.
Команда задаст три вопроса:
- Путь для сохранения — по умолчанию ~/.ssh/id_rsa. Нажмите Enter, чтобы принять.
- Кодовая фраза (passphrase) — дополнительный пароль для защиты закрытого ключа. Можно оставить пустой, нажав Enter дважды.
- Подтверждение кодовой фразы — повторите её или снова Enter.

После этого в каталоге ~/.ssh/ появятся два файла: id_rsa и id_rsa.pub.

По умолчанию ssh-keygen создаёт ключ RSA длиной 3072 бита. Для явного указания алгоритма и длины используют флаги -t и -b.

Современная альтернатива — алгоритм Ed25519, который короче, быстрее и не менее надёжен. Файлы в этом случае будут называться id_ed25519 и id_ed25519.pub.

Чтобы сервер принял ваш открытый ключ, его содержимое нужно добавить в файл ~/.ssh/authorized_keys на удалённой машине. Для этого есть специальная команда: `ssh-copy-id user@192.168.1.10`. Она сама прочитает ~/.ssh/id_rsa.pub и добавит его на сервер. После этого подключение по ключу заработает без пароля. Если ssh-copy-id недоступна, можно сделать то же вручную: `cat ~/.ssh/id_rsa.pub | ssh user@192.168.1.10 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"`.

scp (Secure Copy Protocol) — утилита командной строки для копирования файлов между двумя машинами по зашифрованному соединению. Под капотом она использует тот же протокол, что и SSH, поэтому если вы уже умеете подключаться к серверу по SSH, scp заработает без дополнительной настройки.

Общая форма команды выглядит так: `scp [флаги] источник назначение`. Источник и назначение могут быть либо локальным путём, либо адресом вида пользователь@хост:путь. Именно двоеточие отделяет адрес сервера от пути на нём — это главный маркер удалённой стороны. После выполнения команды система запросит пароль пользователя alice (если не настроена аутентификация по ключу). Затем появится прогресс-бар с именем файла, скоростью передачи и процентом завершения.

Адрес удалённого пути (remote path) строится по схеме: `пользователь@хост:путь`. По умолчанию scp работает только с файлами. Попытка скопировать каталог без дополнительного флага завершится ошибкой. Флаг -r (recursive) заставляет команду обходить каталог целиком — со всеми вложенными файлами и подкаталогами.

По умолчанию SSH (и scp) использует порт 22. Если администратор сервера сменил порт — например, на 2222 — нужен флаг -P (Port). Обратите внимание: в отличие от ssh, где флаг пишется строчной -p, у scp он заглавный.

Если scp — это инструмент для разового копирования, то rsync — инструмент для синхронизации. Его главное преимущество: при повторном запуске он передаёт только изменившиеся части файлов, а не всё целиком. Это критично, когда нужно регулярно обновлять резервную копию или синхронизировать большую директорию.

Базовый синтаксис: `rsync [флаги] источник назначение`. Обратите внимание на слэш в конце project/. Это важно: с слэшем rsync копирует содержимое папки, без слэша — саму папку целиком внутрь назначения.

Ключевые флаги:
- -a: Архивный режим (archive mode): рекурсия + сохранение прав, временных меток, символических ссылок, владельца
- -v: Подробный вывод (verbose): показывает каждый передаваемый файл
- -z: Сжатие данных при передаче по сети
- --delete: Удаляет из назначения файлы, которых нет в источнике
- --dry-run: Пробный запуск: показывает, что будет сделано, не изменяя файлы

Без --delete rsync только добавляет и обновляет файлы. Если вы удалили файл в источнике, в назначении он останется. Флаг --delete исправляет это: `rsync -av --delete project/ user@192.168.1.10:/home/user/project/`. Теперь назначение будет точным зеркалом источника. Используйте этот флаг осторожно: файлы в назначении будут удалены без предупреждения.

rsync работает и без сети — для локального копирования между папками. `rsync -av /data/backup/ /mnt/external/backup/`

Это быстрее, чем cp -r, потому что rsync пропускает неизменившиеся файлы.
