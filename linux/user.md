Каждый пользователь в Linux описан строкой в файле /etc/passwd. Этот файл существует с первых версий Unix и по сей день остаётся главным реестром учётных записей системы. Он доступен для чтения любому пользователю — это намеренно, потому что многие программы обращаются к нему, чтобы узнать, кому принадлежит тот или иной процесс или файл.

Каждая запись занимает одну строку и содержит семь полей, разделённых двоеточием: `username:password:UID:GID:GECOS:home_dir:shell`.

UID (User ID) — главный идентификатор пользователя в ядре. Именно по нему, а не по имени, система проверяет права доступа. UID 0 всегда принадлежит root. Обычные пользователи получают UID начиная с 1000 (в большинстве дистрибутивов).

GID (Group ID) в этом поле — основная группа (primary group) пользователя. Файлы, созданные пользователем, по умолчанию получают именно этот GID.

Поле GECOS исторически использовалось для хранения контактных данных сотрудников. Сегодня оно часто содержит только полное имя или вовсе остаётся пустым.

Поле shell определяет, какая программа запустится, когда пользователь откроет терминал. Если здесь стоит /usr/sbin/nologin или /bin/false — интерактивный вход для этой учётной записи заблокирован. Так настраивают системные аккаунты вроде www-data: они нужны для запуска процессов, но входить в систему от их имени не должен никто.

Группа (group) — это именованный набор пользователей, которым система даёт одинаковые права доступа к файлам и ресурсам. Один пользователь может состоять в нескольких группах одновременно.

Все группы системы хранятся в файле /etc/group.

Обратите внимание: если пользователь состоит в группе как в основной, он не всегда отображается в четвёртом поле этой группы — его принадлежность прописана в /etc/passwd через GID.

В Linux каждый пользователь имеет числовой идентификатор — UID (User ID). Система принимает решения о правах доступа именно по этому числу, а не по имени. Пользователь с UID 0 называется root и обладает абсолютными правами в системе. Система просто не проверяет разрешения, если UID равен 0.

Разделение на привилегированных и обычных пользователей — намеренное архитектурное решение. В Linux работает принцип: обычный пользователь может навредить только своим файлам, но не системе в целом.

В современных дистрибутивах (Ubuntu, Debian, Fedora) прямой вход под root по умолчанию отключён, а для выполнения привилегированных операций используется механизм временного повышения прав.
