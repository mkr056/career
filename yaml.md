Формат сериализации данных — это определенный стандарт и набор правил, по которым сложные структуры данных из оперативной памяти компьютера (например, объекты, списки, словари в коде программы) переводятся в простую последовательность байт или текст.

YAML (YAML Ain't Markup Language) — формат сериализации данных, который читается (и редактируется) почти как обычный текст, но требует строгой дисциплины в отступах. Его чаще всего используют для файлов конфигурации.

Отступ задаётся только пробелами, символ табуляции недопустим. Стандарт — два пробела на уровень вложенности. Смешивание разного числа пробелов на одном уровне тоже приводит к ошибке. У элемента списка вложенность считается после `- `.

Базовые типы данных:
- скаляр (scalar) — одно значение: строка, число, булево значение;
- список (sequence) — элементы через дефис с пробелом. Обязательно с пробелом между;
- словарь (mapping) — пары «ключ: значение». Обязательно с пробелом между.

```yaml
name: web
port: 8080
tags:
  - prod
  - api
config:
  timeout: 30
  retries: 3
```

Для многострочного текста используются два блочных индикатора: | сохраняет переносы строк как есть, > сворачивает их в пробелы.

```yaml
description: |
  Первая строка.
  Вторая строка.
summary: >
  Это будет одна
  строка через пробел.
```

Нельзя писать сам текст на той же строке, где стоит индикатор.

Если после многострочного текста есть продолжение файла, то по умолчанию оба индикатора (`|` и `>`) оставляют ровно один символ переноса строки в самом конце текста, удаляя все последующие пустые строки. Вы можете изменить это поведение с помощью модификаторов `+` или `-`, добавив их прямо к символу.

- `-`: Удаляет вообще все переносы строк в конце блока (включая стандартный последний).
- `+`: Сохраняет абсолютно все пустые строки и переносы, которые вы оставили в конце блока.

Переносы строки до и между строк текста выводятся как есть.

Без кавычек YAML сам пытается угадать тип значения, и иногда угадывает неверно. Кавычки обязательны в трёх случаях:
- для строк, похожих на числа с точками, например версия "3.10" — без кавычек парсер превращает её в число 3.1, теряя завершающий ноль;
- для строк on, off, yes, no — часть парсеров читает их как булево значение. Классический пример — ключ on в GitHub Actions, который без кавычек может превратиться в true;
- для строк со спецсимволами: двоеточием с пробелом после него, решёткой после пробела (начало комментария), фигурными скобками.

Якорь (anchor, &имя) помечает узел для повторного использования, ссылка (alias, \*имя) подставляет его содержимое в другом месте файла. Это избавляет от копирования одинаковых блоков конфигурации.

```yaml
defaults: &defaults
  timeout: 30
service:
  <<: *defaults
  port: 8080
```

Строка <<: \*defaults — ключ слияния (merge key): он вставляет в словарь все пары из узла, помеченного якорем.

Синтаксис проверяют двумя способами: линтером `yamllint file.yaml`, который дополнительно следит за стилем, и коротким вызовом `python -c "import yaml,sys; yaml.safe_load(open(sys.argv[1]))" file.yaml` (нужен установленный пакет PyYAML), который просто убеждается, что файл валиден.
